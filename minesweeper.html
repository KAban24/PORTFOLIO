GRaO.mc

Сапёр, который не задыхается на поле 1000×1000. Один мегабайт памяти на миллион клеток, AVX2 для проверки победы, BFS для открытия пустых зон и DirectX 11 для рендера без лишних состояний.

О ПРОЕКТЕ

GRaO.mc — это не просто сапёр. Это проверка того, насколько далеко можно зайти с оптимизацией: поле до миллиона клеток, спокойный рендер, быстрые вычисления и интерфейс, который остаётся отзывчивым. Название расшифровывается как Great Render and Optimization — million cells.

Внутри — ручное управление памятью, битовые поля, SIMD-инструкции AVX2, итеративный BFS, процедурная генерация звука и пять визуальных тем. Всё написано на C++20 под Windows, без игровых движков и тяжёлых фреймворков.

Проект вырос из желания проверить: что будет, если относиться к классической игре как к системной задаче, а не как к учебному примеру. Ответ — миллион клеток, 150 000 мин и примерно 1 МБ памяти под игровое поле.

ЧТО ВНУТРИ

Восемь решений, из-за которых проект живёт на миллионе клеток и не превращается в слайд-шоу.

01

Один байт на клетку

Состояние клетки упаковано в битовое поле. static_assert гарантирует размер: миллион клеток — 1 МБ.

02

AVX2-проверка победы

CheckWinConditionSIMD обрабатывает 32 клетки за итерацию через _mm256_* и popcount.

03

BFS без рекурсии

IterativeUnlock использует стек вместо рекурсии — никакого переполнения на больших полях.

04

DirectX 11 Flip Discard

Минимальная задержка и отсутствие разрывов. Рендер через DXGI с флип-моделью.

05

Frustum culling

Рисуются только видимые клетки. Остальные отбрасываются до попадания в ImDrawList.

06

Пять тем

Cyber Emerald, Cyberpunk Neon, Classic Win95, Sunset Vaporwave и Deep Space — с анимированными фонами.

07

Процедурный звук

PCM синтезируется на лету в waveOut. Ни одного wav/mp3-файла: синусы, конверты, FM.

08

Миникарта и камера

Зум, панорама, WASD и телепорт по клику на миникарту. Ориентироваться на миллионе клеток реально.

Упаковка состояния

Каждая клетка — ровно один байт. visible, mine, flag, nearbyNumber и bombNearby живут в одном bitfield. Размер проверяется на этапе компиляции.

GameLogic.hC++20
#pragma pack(push, 1)
struct fieldState {
    uint8_t visible      : 1;
    uint8_t mine         : 1;
    uint8_t flaged       : 1;
    uint8_t nearbyNumber : 1;
    uint8_t bombNearby   : 4;
};
#pragma pack(pop)

static_assert(sizeof(fieldState) == 1);

Проверка победы на AVX2

Вместо обхода миллиона клеток по одной — 32 байта за итерацию, маски и popcount. Проверка победы перестаёт быть узким местом.

GameLogic.hAVX2
__m256i maskVisible = _mm256_set1_epi8(0x01);
__m256i maskMine    = _mm256_set1_epi8(0x02);

for (size_t i = 0; i < total; i += 32) {
    __m256i chunk = _mm256_loadu_si256(
        reinterpret_cast<const __m256i*>(&field[i])
    );
    __m256i revealed = _mm256_and_si256(chunk, maskVisible);
    __m256i mines    = _mm256_and_si256(chunk, maskMine);
    revealedCount += __popcnt(_mm256_movemask_epi8(revealed));
    mineCount     += __popcnt(_mm256_movemask_epi8(mines));
}

Итеративный BFS

Открытие пустой области не уходит в рекурсию. Явный стек переживёт любое поле и не положит поток.

GameLogic.hBFS
std::vector<int> stack{ startIndex };
while (!stack.empty()) {
    int current = stack.back();
    stack.pop_back();

    for (int neighbor : neighbors(current)) {
        if (canReveal(neighbor)) {
            reveal(neighbor);
            stack.push_back(neighbor);
        }
    }
}
